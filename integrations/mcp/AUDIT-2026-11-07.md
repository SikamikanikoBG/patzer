# Patzer MCP audit — 2026-11-07

Scope: `feature/mcp-chess-review` in `MousaXD/patzer`. This is an audit of the bridge I originally wrote, not a certification of the ChatGPT cloud connection.

## Findings and remediation

| Severity | Finding | Action/status |
| --- | --- | --- |
| CRITICAL | Initial bridge required a static Bearer API key on every MCP request, while the currently documented ChatGPT custom MCP connection does not accept arbitrary API keys. The original ZIP would not connect using the described method. | Replaced ChatGPT deployment path with local stdio transport + OpenAI Secure MCP Tunnel. New portable plugin generator requires an actual `tunnel_id` and sets MCP auth `none`; it does not package any credential. Cloud connection still unverified. |
| HIGH | Proposed Tailscale Funnel on `:8443` did not exist, would expose another publicly reachable endpoint, and could not satisfy the ChatGPT auth requirement. | Removed that deployment recipe. No changes to the existing Tailscale Funnel on `:443` or local Caddy gateway. |
| HIGH | Previous seven tests used only a fake backend, and did not prove Patzer REST authentication, game retrieval or real Stockfish analysis. | Added `integration-real.mjs`: actually launches Patzer on a temporary DB, creates a disposable account/game, and checks API login, game retrieval, position analysis, full game analysis and cached review. Verified all checks pass. |
| HIGH | Original setup did not check ChatGPT workspace creation permissions or OpenAI Platform tunnel requirements. | Documented permissions (Business workspace admin/owner or appropriate Enterprise/Edu developer access), Platform Tunnels Read+Manage/Read+Use, real `tunnel_id` and local runtime key. Cannot create a working connection without these. |
| MEDIUM | Private API endpoint was assumed safe to expose behind Funnel, but authentication was incompatible. | HTTP bridge now explicitly refuses non-loopback binds, validates Origin, requires a long Bearer secret and advertises that it is for local/non-ChatGPT clients only. Stdio mode opens no listening socket. |
| MEDIUM | Patzer itself defaults to `HOST=0.0.0.0`, despite the recommendation of local-only operation. | Updated startup instructions to `HOST=127.0.0.1 npm run dev` to avoid exposing the chess API on the LAN. |
| MEDIUM | One method generates AI prose by buffering an upstream SSE response; an LLM may be unavailable or the generation can exceed host timeouts. | Documented as unverified. Stockfish analyses and expected `llm_not_configured` failure were verified, not full AI-prose generation. |
| LOW | Game listing has no pagination in the current Patzer API. | Limited to latest 100 games; documented. |
| LOW | Tool hint metadata was missing, making write operations less obvious to clients. | Added MCP annotations for read-only vs. write operations and prompt-injection handling instructions. |

## Verification evidence

- `node --test integrations/mcp/test.mjs` — 7/7 pass, mock HTTP boundary tests, including auth, protocol initialization and AI review SSE decoding.
- `node integrations/mcp/integration-real.mjs` — Patzer v7.18.1 server launched in **temporary directory**, real login, game fixture, Stockfish 17 position evaluation, and full game analysis; checks pass. No access to the original `data/chess.db`.
- `npm exec --yes --package=@modelcontextprotocol/inspector -- mcp-inspector --cli env PATZER_USERNAME=test PATZER_PASSWORD=test node integrations/mcp/stdio.mjs --protocol-era legacy --method tools/list --strict --format json` — succeeds with all 8 tool definitions. An initialize probe also succeeds using Inspector's automatic protocol negotiation.
- `node integrations/mcp/scripts/build-plugin.mjs tunnel_0123456789abcdef0123456789abcdef` — a **synthetic ID used for syntax checking only**; generated `mcp.json` has `type=streamable-http`, `tunnelId` and `auth.type=none`, with no direct URL or secret. Artifact subsequently deleted to prevent confusing a fake ID with a real connection.
- No Patzer process was running in the original checkout, no localhost 8800/8811 listening, and the existing Tailscale Funnel still pointed solely to the original Chat On Steroids endpoint when audited.

## What has NOT been verified

1. A valid Platform tunnel ID, runtime key, permissions, tunnel-client installation or a live Secure MCP Tunnel connection. No `tunnel-client` executable was found on the machine.
2. ChatGPT plugin registration, discovery, permissions and `list_games` tool invocation from the actual ChatGPT UI.
3. Patzer login against the user's existing credentials and original database (no credentials provided or retrieved).
4. End-to-end AI coach prose with Ollama/vLLM (test instance intentionally had no configured LLM).
5. Long-running traffic, multi-user authorization isolation, public exposure hardening, or production availability/systemd service.

**Conclusion:** Core adapter and local MCP discovery now have meaningful evidence. Cloud plugin deployment remains blocked on external tunnel credentials and workspace privileges; do not describe this as end-to-end complete until a real ChatGPT tool call succeeds.

Current references: https://developers.openai.com/api/docs/guides/custom-mcp-server ; https://developers.openai.com/plugins/build/auth ; https://developers.openai.com/api/docs/guides/secure-mcp-tunnels ; https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt .

## Follow-up: local runtime setup (2026-11-07)

- Existing Patzer checkout built for production successfully (`npm run build`) without merging into the fork or changing the original tracked source; `patzer.service` is active/enabled in user systemd, bound to localhost port 8800; `/api/health`, `/api/setup/status` and `/` responded successfully.
- Original SQLite database had 21 games and 13 analyses before startup. A consistent pre-start backup made using Python sqlite3 backup API passed `PRAGMA integrity_check` and is stored in `data/backups/` under the original installation.
- Official `tunnel-client` v0.0.20 Linux amd64 installed in `~/.local/bin/` from the `openai/tunnel-client` release with its official `SHA256SUMS.txt` verified. `tunnel-client help quickstart` works.
- The machine does not currently provide `CONTROL_PLANE_TUNNEL_ID`, `CONTROL_PLANE_API_KEY`, `OPENAI_ADMIN_KEY`, or `OPENAI_API_KEY`. No login credentials for the actual Patzer account are configured for the bridge, and no ChatGPT plugin was created.
- Added a local interactive credential setup script that stores the user's Patzer password in an ignored, mode-600 file, and verifies API login through `list_games`. This script awaits user's own secure password entry; it was not run on the user's behalf.
- Re-ran mock, isolated-real, and official MCP Inspector tests after adding file-based credential support; all passed. Real ChatGPT connectivity remains unverified.
